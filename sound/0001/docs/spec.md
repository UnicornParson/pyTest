Генератор звуков для видеоигр — архитектура проекта

Для проекта с видеокартой на 3 ГБ VRAM оптимально не делать одну нейросеть единственным генератором. Лучше использовать гибридную архитектуру: небольшая локальная AI-модель + процедурный DSP-движок.

Основная AI-модель: TangoFlux

TangoFlux — text-to-audio модель примерно на 515 млн параметров, ориентированная на генерацию звука из текста. Она подходит как AI-компонент генератора игровых SFX.

Важно: 515 млн параметров не означает, что модель гарантированно будет комфортно работать в 3 ГБ VRAM. Поэтому основную архитектуру следует строить так, чтобы генерация могла выполняться на CPU/offload, а GPU использоваться только там, где модель реально помещается.

Почему не AudioGen

AudioGen хорошо подходит для генерации звуковых эффектов, окружения и Foley, однако AudioGen Medium значительно тяжелее и не подходит для видеокарты с 3 ГБ VRAM.

Почему не Stable Audio Open

Stable Audio Open интересна для SFX, Foley и ambient-звуков, но для локального запуска на 3 ГБ VRAM она слишком тяжёлая для роли основной модели.

Рекомендуемая архитектура

ТЕКСТ
  ↓
маленькая локальная LLM
  ↓
Text → JSON
  ↓
SFX PARAMETERS
  ↓
┌──────────────────┬──────────────────┐
│                  │                  │
↓                  ↓                  ↓
PROCEDURAL DSP     TangoFlux          другие DSP-слои
CPU                AI SFX             CPU
│                  │                  │
└──────────────────┴──────────────────┘
                   ↓
                  MIX
                   ↓
            POST-PROCESSING
                   ↓
                WAV / OGG

Пример

Пользователь пишет:

«Огромный огненный магический взрыв в пещере»

Маленькая локальная модель превращает запрос в параметры:

{
  "type": "explosion",
  "element": "fire",
  "size": 0.95,
  "power": 1.0,
  "low_end": 0.9,
  "noise": 0.8,
  "magic": 0.7,
  "reverb": 0.95,
  "duration": 2.8
}

Затем генератор распределяет работу:

low_end → procedural boom
noise → procedural noise
magic → TangoFlux
fire → procedural fire/noise
reverb → DSP

После этого все слои смешиваются и обрабатываются.

Почему такой подход подходит для 3 ГБ VRAM

Большую часть простых звуков можно создавать полностью процедурно, не используя нейросеть.

Например:

- удары;
- взрывы;
- шаги;
- UI-звуки;
- лазеры;
- выстрелы;
- whoosh;
- электрические разряды;
- простые магические эффекты.

AI можно использовать там, где процедурный синтез даёт менее интересный результат: сложные магические эффекты, атмосферные звуки, необычные текстуры и кинематографические SFX.

Рекомендуемый стек

Text → параметры:
маленькая локальная LLM

TangoFlux

Процедурные эффекты:
собственный DSP-движок

Обработка:
NumPy / SciPy

PySide6

GPU:
3 ГБ VRAM

CPU:
основная рабочая нагрузка

Порядок разработки

1. Процедурный DSP-синтезатор.
2. Система слоёв.
3. Система тегов.
4. Генерация вариаций через seed и случайные параметры.
5. EQ, compressor, limiter, fade и нормализация.
6. GUI.
7. Подключение TangoFlux.
8. Text → JSON через маленькую локальную LLM.
9. Экспорт WAV/OGG.
10. Библиотека и поиск созданных игровых звуков.

Итоговая идея

Пользователь пишет текст или выбирает теги. Маленькая локальная модель превращает запрос в структурированные параметры. Процедурный движок и TangoFlux создают отдельные звуковые слои. Затем они смешиваются, обрабатываются и экспортируются в WAV/OGG.

Такой подход позволяет создать полноценный локальный генератор игровых SFX, не требующий мощной видеокарты и не зависящий от одной тяжёлой нейросети.
